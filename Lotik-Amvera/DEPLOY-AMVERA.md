# Lotik на Amvera

Архив для Amvera разворачивается как одно приложение Docker. В одном процессе Node.js работают сайт, Mini App, Telegram webhook и фоновый парсер. SQLite доступна тому же процессу. Используйте одну реплику. Файлы для отдельного развёртывания на Ubuntu остаются в исходном проекте.

В существующем GitHub-репозитории оставьте `amvera.yaml` в корне, а `Dockerfile.amvera`, файлы `*.mjs` и папку `public` в `Lotik-Amvera/`. Настроенный порт контейнера — **3000**, постоянное хранилище — **/data**. Lotik использует Node.js 24 и стандартный модуль `node:sqlite`. [Настройка Docker в Amvera](https://docs.amvera.ru/applications/configuration/docker.html).

## Первый запуск

1. Создайте приложение в Amvera и загрузите содержимое архива в корень кода или отправьте его в репозиторий проекта.
2. Добавьте HTTPS-домен во вкладке «Домены» и заполните переменные рабочего режима ниже. Для проверки авторизации и сохранения поисков достаточно `PARSER_MODE=off`. [Домены Amvera](https://docs.amvera.ru/applications/configuration/network.html).
3. После развёртывания проверьте `/health`, откройте Mini App из меню бота и сохраните поисковую ссылку. Закройте и снова откройте приложение. Убедитесь, что в разделе «Репозиторий → Data» есть `radar.sqlite` и что после перезапуска используется тот же файл.

## Рабочий режим

В разделе «Переменные» задайте:

| Имя | Значение |
| --- | --- |
| `MODE` | `production` или оставить пустой. Старое значение `demo` замените |
| `PUBLIC_URL` | HTTPS-адрес Mini App из вкладки «Домены» |
| `WEB_PUBLIC_URL` | Необязательный HTTPS-адрес отдельного сайта. По умолчанию используется `PUBLIC_URL` |
| `DATA_DIR` | `/data` по умолчанию в контейнере. Сохраните существующий путь на постоянном томе |
| `BOT_TOKEN` | Токен из BotFather. Добавьте как секрет |
| `WEBHOOK_SECRET` | Случайная строка длиной 32–256 символов из букв ASCII, цифр, дефиса и подчёркивания. Добавьте как секрет |
| `OWNER_TELEGRAM_ID` и `SUPPORT_CONTACT` | Telegram ID владельца и контакт поддержки |
| `PARSER_MODE` | `off` при первом запуске. После согласования доступа к Авито используйте `live` и `AVITO_ACCESS_APPROVED=1` |
| `ENABLE_CARD_CHECKOUT` | `0` |

Оставьте поля API.SH и ЮKassa пустыми при первичной настройке. Оформление новых платежей отключено в релизном контейнере до проверки с тестовым магазином ЮKassa. При обновлении сохраняйте исходный режим `YOOKASSA_TEST` и путь к SQLite, чтобы приложение продолжало читать заказы и доступы из соответствующего режима.

Когда `/health` отвечает по HTTPS, при первичной настройке зарегистрируйте webhook и кнопку Mini App командой `npm run setup:telegram` на компьютере с Node.js 24. Скрипт берёт те же значения из локального `.env`; файл с секретами не загружайте в Amvera. [Переменные и секреты Amvera](https://docs.amvera.ru/applications/configuration/variables.html).

## База данных

Рабочая база находится в `/data/radar.sqlite`. При повторном развёртывании используйте тот же проект и постоянное хранилище. Контейнер по умолчанию использует журнал SQLite `DELETE`. Проект рассчитан на одну реплику и доступ к SQLite с одного узла. [Постоянное хранилище Amvera](https://docs.amvera.ru/applications/storage.html), [ограничения SQLite WAL](https://www.sqlite.org/wal.html).

При переносе в другой проект сначала разверните приложение, чтобы Amvera создала хранилище. На старом экземпляре остановите новые записи и сделайте согласованную резервную копию через `node parser-admin.mjs backup /путь/к/копии.sqlite` с его прежним `DATA_DIR`. Остановите приложение в целевом проекте, снимите копию его текущей базы и загрузите снимок под именем `radar.sqlite` в корень вкладки **Data**. Поиски старого демо относились к общему ID 0 и не привязываются к Telegram-аккаунтам. [Загрузка SQLite в Amvera](https://docs.amvera.ru/databases/sqlite.html).
